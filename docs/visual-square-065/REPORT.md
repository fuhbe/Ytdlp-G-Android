# Square Liquid Glass — 0.6.5 test build

Base: approved **0.6.4**, commit `30a347f48cbf04ccf0973b3c5a2f6e869ecb81ed`.
Branch: `visual/square-liquid-glass-motion`. The published stable release, tags
and default branch are preserved. This is an isolated visual test, not a new
stable release or a claim of pixel-identical iOS behavior.

## What changed

One shared clear-glass control now drives the existing bottom navigation,
MP3/MP4, Downloads/Completed and Normal/ZIP selectors. The pane follows a
horizontal drag before committing its existing action on release. Independent
spring channels deform its measured bounds according to motion, then settle
elastically. Finger-driven radial light, a directional specular rim, captured
backdrop refraction, frosting, shadow and inner shadow replace the blue fill.

The real Square source was inspected and adapted, not merely cited as
inspiration. The exact originals and hashes are retained under
[`minimal/vendor/square`](../../minimal/vendor/square/PROVENANCE.md), pinned to
`17ed2b87974cf6fec9c531ef3f1438448bb2b729`. That document maps each original to
the compiled adaptation and lists intentional differences. Apache and GPL
notices ship inside the APK and corresponding source ZIP.

The existing Backdrop **1.0.3** native layer/blur/lens implementation is retained.
Its exact corresponding source JAR is already bundled. Square's newer library
fork would require broader toolchain changes; no SDK, Kotlin, Compose, runtime,
network or media dependency upgrade is made for this visual change.

Labels and icons are drawn once above the glass. The backdrop excludes the
pane itself and its labels, avoiding recursive capture and ghost text. Actual
child bounds determine selection and width, including RTL and changing counts.
The pane remeasures while deforming, instead of stretching a captured bitmap.
Existing taps, keyboard/accessibility actions, safe insets, scrolling and the
actual quality dropdown are retained. No download callback is invoked during a
drag, on cancellation, outside release or selecting the current destination.

## Fallbacks

| Device capability | Material |
| --- | --- |
| API 26–30 | Clear tinted film, gradient lighting/rim and spring/deformation gestures; no AGSL or background blur claim. |
| API 31–32 (including Android 12) | Real captured-background RenderEffect blur, compatible reflections and gestures; no AGSL refraction claim. |
| API 33+ with sufficient memory/hardware acceleration | Native captured-background lens and directional shader specular, bounded to 45% of the pane's shorter edge. |
| Low RAM, memory class below 192 MB, power saver or software window | Same usable selectors with the inexpensive tint/lighting path. |
| Lens/rim shader rejected | Preserve blur and use the compatible rim; log a capability warning without URLs or media metadata. |
| System animation duration scale zero | Selection settles immediately; no infinite shimmer or animation loop. |

## Verification and evidence

`BASELINE.json` pins every existing minimal-app source hash. `BASELINE_TESTS.json`
records the original **119 test identities** (118 passed, one pre-existing host
Skia shader limitation skipped). `verify_scope.py` checks all original test
sources, runtime, media/queue/storage/export implementations, resources,
wallpapers, native/bootstrap rules and dependencies are unchanged. It permits
only exact visual, selected-semantics and legal-credit substitutions in
MainActivity, besides version metadata and the isolated selector implementation.

The new gesture tests cover API 26/28/31/**32**/33/35, actual model format and ZIP
changes, history filtering, measured unequal widths, RTL, intermediate motion,
valid release, cancellation, vertical/outside gestures, two fingers, changing
download counts, and zero animation duration. A test exposed a cancellation
bug where the second finger could still click a child; the recognizer now
consumes the owned multi-pointer sequence through release.

`before/` and `after/` contain the same eight UI states generated by the real
Compose layout with fixture metadata. `motion/light/` and `motion/dark/`
contain **48 captured AppContent frames and eight GIFs** covering all four
selectors. GIFs only replay captured frames; no visual effects or intermediate
frames are fabricated. `EVIDENCE.json` identifies the renderer and frame hashes.
These are **software/fallback previews**, not photos or proof of native AGSL,
physical touch fidelity, FPS, battery use or a new live YouTube download test.

`SquareGlassDeviceTest` adds a native API33+ probe of the same production
component against a checkerboard backdrop, comparing blur-only and lens paths
at two actual positions and checking center preservation versus edge movement.
It also checks one release callback. The matching optimized instrumentation
APK includes this and all seven existing device tests.

**Native acceptance is pending:** no attached Android device or usable hardware
accelerated emulator is available in this environment. Building the eight
device tests is not running them. The instructions below make this check
repeatable and collect actual device screenshots/pixel counts. No thermal or
frame-time improvement is asserted without device measurements.

The machine-readable `visual-square-delivery.json`, JUnit XML, media fixture
smoke report, R8/Dex bootstrap checks, positive/negative ZIP regression, APK
metadata/signatures and exact source checks accompany the Actions artifact.

## Run the native checks

Back up your app data first. Test and stable APKs may have different development
signing keys. An Android signature conflict prevents an in-place update; do not
uninstall a working copy without preserving its queue/history/files. The same
application ID is retained, so these builds cannot be installed side by side.

On an ARM64 Android device with USB debugging enabled:

```sh
adb devices
adb install -r Ytdlp-G.apk
adb install -r Ytdlp-G-tests.apk
adb shell am instrument -w -e class com.fuhbe.ytdlpg.simple.SquareGlassDeviceTest com.fuhbe.ytdlpg.minimal.test/androidx.test.runner.AndroidJUnitRunner
adb pull /sdcard/Android/data/com.fuhbe.ytdlpg.minimal/files/square-glass-device/
```

Run the existing visual/native suite separately after pausing jobs:

```sh
adb shell am instrument -w com.fuhbe.ytdlpg.minimal.test/androidx.test.runner.AndroidJUnitRunner
```

Check light/dark, MP3/MP4, Normal/ZIP, history and all three destinations; slow
drag/reverse/release/cancel, large fonts, rotation, power saver and animation
duration zero. Verify progress and download actions remain available. On API32,
expect blur and compatible lighting rather than AGSL. On API33+, the moving
native pixel probe must pass before accepting genuine device refraction.

For a failure, collect redacted diagnostics with `adb logcat -d -s AndroidRuntime
YtdlpG-Glass`; omit URLs, query strings, account names and downloaded file paths.
